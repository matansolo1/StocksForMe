Verification Summary: Both strategies operate on completely separate execution tracks. The scan_universe_generator() function accepts strategy_mode as a parameter and uses conditional branching to ensure that Mean Reversion and Momentum filters never cross-contaminate. 📉

Mean Reversion Strategy

Catching oversold bounces in fundamentally strong stocks

Active Filters & Criteria

Target RSI Threshold < 30
Price vs. SMA 20 Below SMA
Stop Loss -3.0%
Take Profit +6.0%
Risk/Reward Ratio 1:2
Global Trend Filter SPY > SMA 200

Entry Logic (Python Implementation)

if strategy_mode == "mean_reversion":   if rsi_prev < target_rsi and current_rsi >= target_rsi:     if current_close < current_sma:       passed_rules = True       rank_score = (sma - close) / volatility

Ranking Mechanism

RankScore = (SMA_20 - Close) / Volatility

Stocks with the largest distance from their mean (normalized by volatility) are prioritized. This creates a Z-Score-like ranking that identifies the most extreme oversold conditions.

Momentum Strategy

Riding established uptrends with RSI confirmation

Active Filters & Criteria

Target RSI Threshold > 55
Price vs. SMA 50 Above SMA
Stop Loss -5.0%
Take Profit +10.0%
Risk/Reward Ratio 1:2
Global Trend Filter SPY > SMA 200

Entry Logic (Python Implementation)

if strategy_mode == "momentum":   if rsi_prev < target_rsi and current_rsi >= target_rsi:     if current_close > current_sma50:       passed_rules = True       rank_score = current_close / high_52w

Ranking Mechanism

RankScore = Current_Close / 52_Week_High

Stocks trading closest to their 52-week highs are prioritized. This identifies the strongest momentum candidates that are breaking out or maintaining leadership positions.

Data Flow Architecture - Strategy Isolation

1

Frontend UI Layer

User selects strategy mode (Mean Reversion / Momentum) and configures parameters (RSI, SL, TP) via dropdown and input fields.

2

Flask Route Handler (app.py)

Receives POST/GET request with strategy_mode, target_rsi, stop_loss_pct, take_profit_pct as isolated parameters. No global state is modified.

3

Scanner Generator (scanner.py)

The scan_universe_generator(strategy_mode, ...) function uses conditional branching to execute ONLY the selected strategy's logic. Parameters are passed explicitly, ensuring zero cross-contamination.

4

Trading Logic (trading_logic.py)

Processes scan results independently. Each strategy's setups are handled in isolation with their own entry/exit rules and position sizing calculations.

5

Database Persistence (data_manager.py)

For LIVE SCANS only: Results are saved to trades_db.json with strategy metadata. DRY RUNS bypass this layer entirely, ensuring no database writes occur.
